# MAC Attack

A folded, quantized systolic MAC array accelerator (a "mini TPU").

**Application: Machine Guardian** — machine-fault detection running on a ZedBoard. Since 27 Oct the model's task
is healthy / faulty from motor vibration (University of Ottawa electric motor dataset, accelerometers; no microphone):
`docs/log.md` section 2, 27 Oct, and `model/README.md`.

## Rules

1. **Pull before you start, push when you finish.**
2. **The ZedBoard projects are tracked with their results** (decision of 18 Oct, `docs/log.md` section 2;
   `.gitignore` lines 1-7 and 33-48), so a teammate can program the board without the 20-minute build. In
   `zed/mac_zed_project/`, git tracks `mac_zed.xpr`, `mac_zed.srcs/`, `mac_zed.runs/` (bitstream, checkpoints,
   reports), `mac_zed.hw/`, and in `mac_zed.sdk/` the `.hdf`, hardware platforms, BSP and apps when they exist
   (design 2 has only the apps so far). Not tracked: `.cache`, `.sim`, `.ip_user_files`, `.Xil`, logs, the SDK
   `.metadata` and the apps' Debug/Release folders. The 18 Oct rule: only builds that met timing and passed on the
   board are pushed, by one person at a time.
   Other Vivado output (e.g. `vivado/mac_attack_project/`) is generated by its Tcl script and not committed.
3. **Clone to a short path with no spaces or non-ASCII characters** (e.g. `C:\work\mac_attack`).
   Vivado 2019.1 rejects non-ASCII paths, and a space breaks File > Launch SDK.
4. **Large files go to Google Drive, not git** — datasets (e.g. the motor recordings, passed to `model/` with
   `--data`), big weight files, etc. The tracked ZedBoard projects (rule 2) are the exception.

## Working together

**One branch per change.** Never edit main directly.
1. In GitHub Desktop: switch to `main`, **Fetch/Pull**, then **Current branch > New branch**,
   named `name/topic` (e.g. `alex/fold-16x16`).
2. Commit as you go, then **Publish branch** and **Create Pull Request**.
3. The other person reviews the diff on GitHub, then merge into `main` and delete the branch.

**Two different ideas?** Make two branches and two pull requests. Compare them, merge the one you
pick, close the other (the closed branch stays on GitHub for reference). For variants you want to
keep long term, use the parameters at the top of the Tcl script (e.g. `P` for 8x8 vs 16x16).

**Architecture changes go in text files**, so they can be reviewed and merged:
`build_block_design` in `zed/create_zed_project.tcl` and `rtl/*.sv`. If you try something in the
Vivado GUI, copy the Tcl commands Vivado logged (Tcl Console, or `vivado.jou`) into the script,
then rerun the script to check it. Tell the other person when you are editing the Tcl script.

**Rebuilding the Vivado project:** Tools > Run Tcl Script > `zed/create_zed_project.tcl`, only to rebuild a broken
project: it runs `create_project ... -force` into `zed/mac_zed_project/` (line 29), which deletes the tracked
project including its SDK apps (`docs/log.md` section 6, 18 Oct). It also builds with `FCLK_MHZ 200` (line 24),
not the committed clocks (design 1: 250 MHz; design 2: asked 225, actual 214.286 MHz). Normally open `mac_zed.xpr`.

### SDK (C code)

- Edit and save in SDK as usual. The app sources live in
  `zed/mac_zed_project/mac_zed.sdk/MAC_attack_V2/src/` and are tracked, so commit and push them.
  For a new version, make a new app (`MAC_attack_V3`) or a branch.
- To open it later: pull, then in Vivado **File > Launch SDK** (workspace `mac_zed.sdk`). If the app
  is missing, **File > Import > General > Existing Projects into Workspace**, pick `mac_zed.sdk`.
- **BSP:** design 1 tracks its BSP (`mac_zed.sdk/MAC_attack_V2_bsp/`) and hardware platform. Design 2 tracks
  neither, and no `.hdf` yet (TODO, Alex: Export Hardware with the bitstream from Vivado). Where the BSP is missing:
  **File > New > Board Support Package**, named exactly `MAC_attack_V2_bsp` (hardware platform
  `system_wrapper_hw_platform_0`, CPU `ps7_cortexa9_0`, OS `standalone`). Without it you get "xil_io.h not found".
- The SDK app's `mac_test.c` is the current one. The 13 Oct copies that were in each design's `zed/` are in
  `archive/` (see `archive/README.md`); `James/` keeps its own copy for his golden model.
