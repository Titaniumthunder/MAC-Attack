# Machine Guardian — Training Run 3 and Expanded Dataset Evaluation

MAC-Attack senior capstone. Deterioration head of the 8 → 32 → 16 → 2 multi-task MLP, seven Paderborn development
bearings, nested leave-one-bearing-out validation, INT8 and RTL verification. Prepared with Claude Code, 3 November 2026.
The tables are generated by `model/report/run3_tables.py` from the saved results in `model/results/supervised/run3/`;
the numbers in the text were taken by hand from those results and from `run1/`, `run2/` and `results/paderborn/`, and
every one was checked by an independent fact-check against the files (section 20 lists them).

## 1. Executive Summary

### What Run 3 set out to do

Runs 1 and 2 trained the network on only three bearings (B02–B04). Run 3 adds four more development bearings from the
Paderborn run-to-failure dataset (B08, B09, B11, B12) and retrains the same 850-parameter network with five candidate
training configurations. The candidates were compared with a nested, bearing-separated protocol, so that the selection
can be judged on bearings it never saw.

> **Key finding:** Run 3 makes the network much **steadier**, through log-compressed inputs and weight decay, and brings
> its first alarm close to the anomaly detector's on five of seven bearings (it comes about 3.5 h later on B08 and never
> on B12). Compared with Runs 1–2 on the same three bearings, the first alarm moves from 7.4 to 16.5 minutes before the
> end on B03, and the unlatched alarm's flicker on B04 drops from 43–47 changes to 1.

> **Key finding:** the network **still does not outperform** the label-free anomaly detector. The likely reason, not
> yet tested by a dedicated experiment, lies in the labels and in B12's data. Every end-stage label on the other six
> bearings is an extreme, worn-out measurement (the largest vibration z-input is 18–51 standard deviations), so the
> network probably learns that only extreme deviation means damage. B12's end stage is only 2.5–3.2 standard deviations
> from its own commissioning on the rear sensor: the spread is inflated by a vibration step at M0061, and its stop was
> probably triggered by the front sensor. The network never alarms on B12.

> **Caution:** with 7 bearings, each with 100 healthy rows from its own commissioning and 5 end-stage rows, the
> labelled metrics are largely met by construction. The healthy rows are the rows the inputs are normalised on, and
> the end-stage rows are extreme. The evidence that matters is per bearing: whether and when the alarm comes, compared
> with the anomaly detector, on bearings that played no part in the design (B08, B09, B11, B12).

> **Caution:** "minutes before the last record" is the time before the experiment was stopped. It is **not** a verified
> time before physical failure or before deterioration began; neither is known. The score is a detector output, not a
> calibrated probability of failure.

## 2. Project Objectives and Current Architecture

Machine Guardian monitors a rotating machine's bearing and raises a warning when it starts to deteriorate. A small neural
network is designed to run in INT8 on our own 8 × 8 systolic-array accelerator on the ZedBoard (Zynq XC7Z020); so far
the trained networks have run only in RTL simulation, not on the board. The ARM processor
extracts the features and runs the alarm logic.

![The 8 → 32 → 16 → 2 multi-task MLP](../../model/results/supervised/run2/figures/dev_architecture.png)

| Part | Run 3 |
|---|---|
| Inputs | 8 per 1.6-s measurement: 6 rear-accelerometer features (ln RMS, ln peak, kurtosis, ln 1–5 kHz and ln 5–20 kHz band energy, crest factor), shaft speed, temperature residual. The six vibration features (speed-corrected) and the speed are z-scores against the bearing's own first 100 operating measurements (its commissioning); the temperature residual comes from a per-bearing thermal model |
| Network | **unchanged**: 8 → 32 → 16 → 2, ReLU, 850 parameters (288 + 528 + 17 + 17) |
| Output 1 | deterioration score p = sigmoid(logit), alarm after 3 consecutive p > 0.5, **latched** (Run 2). **Trained** |
| Output 2 | Motor Health Index, HI = 100 % × sigmoid(h). **Untrained**, frozen at its initial weights and checked bit-identical after every training, because no measured severity labels exist |
| Hardware | INT8 weights, INT32 biases, 22-bit accumulators, 14 passes of the 8 × 8 array, both heads in one 16 × 2 last layer |

### 4.3 Sampling frequencies and operating regimes

- **Sampling rates.** B08 and B09 are sampled at 128 kHz, B11 and B12 at 64 kHz, matching the description. `paderborn.py`
  detects the rate per file from its time vector. At 64 kHz the 20–64 kHz band cannot be computed in full (its upper
  part lies above the 32 kHz Nyquist frequency) and is left empty, and the 42.67-kHz signal is resampled by 2/3, so the A42 profile the model uses is
  identical in definition for both rates.
- **Operating regimes.** All four new bearings run under Gaussian random dynamic load, where Runs 1–2 had only
  sinusoidal load. B11 and B12 run at constant static (3,000 N) and dynamic (1,000 N) load with variable speed. Every
  speed set point lies inside the logged range; B09's recorded dynamic load does not (table 4.4).
- **The prototype anomaly detector cannot run on B11 and B12.** It uses the 20–64 kHz band, so every score is NaN at
  64 kHz. The same detector on the 42.67-kHz features (A, F42, speed) runs on all seven bearings and is the common
  reference in this report.

## 6. Feature Extraction and Preprocessing

1. **Per measurement** (`paderborn.py`, unchanged): the rear accelerometer at 42.67 kHz is converted to g (10 g/V), and
   its RMS, peak, kurtosis and crest factor are computed; band energies 1–5 kHz and 5–20 kHz come from the full-rate
   spectrum.
2. **Per bearing** (`mtl_inputs.py`, unchanged):
   - Warm-up rows are removed.
   - On the first 100 operating measurements, each feature is fitted as f = b0 + b1 · ln rpm.
   - z = (f − fit) / σ.
   - Speed gives x7.
   - A first-order thermal model gives the temperature residual x8, which is 0 until the model is calibrated, and 0
     throughout if the bearing fails the thermal validity rule (B08).
3. **Run 3's two input variants (the ARM computes them, so the hardware is unchanged):**
   - **clip16** (Runs 1–2): x = clip(z, −16, +16). INT8 step 16/127 = 0.126.
   - **slog** (candidates C and E): x = sign(z) · ln(1 + min(|z|, 10,000)). This keeps the order of values beyond 16
     instead of flattening them, and is almost linear near 0. INT8 step ln(10,001)/127 = 0.0725.
4. **Temperature variants:** x8 as computed (A, B, C), or x8 = 0 on every row in training and in use (D, E).

**No measurement of a validation or held-out bearing is used to fit anything shared across bearings.** Each bearing is
normalised on its own first 100 measurements, as a newly installed unit would commission itself. This has one
consequence to keep in mind: the healthy labels are exactly that commissioning window, so their z-inputs are near 0 by
construction.

### 7.2 The validation protocol: nested leave-one-bearing-out

![Nested leave-one-bearing-out](../../model/results/supervised/run3/analysis/figures/diagram_nested_lobo.png)

- **Outer loop.** Each of the 7 bearings is held out in turn. The network is trained on the other 6 and scored on every
  measurement of the held-out bearing.
- **Inner loop (model selection).** For each outer bearing, every candidate is trained on 5 of the remaining 6 and
  validated on the 6th, six times over. The candidate with the best inner score is chosen, then judged on the outer
  bearing. 7 × 6 × 5 × 5 = 1,050 inner trainings.
- **Selection rule (fixed in advance).** A lexicographic order on the means:
  1. fewest healthy-reference rows alarmed;
  2. highest end-stage recall;
  3. fewest alarm-state changes of the **unlatched** alarm (stability, which needs no labels);
  4. lowest log-loss on the labelled rows.

  Alarm timing is never used, because the onset of damage is unknown.
- **Final model.** The same rule applied to the 7-fold outer results picks the deployment candidate, which is then
  trained on all 7 bearings (5 seeds). No held-out data is left for it, so the nested results are its performance
  estimate.

**Leakage controls (in the code):**

- `splits.assert_development` runs on every training set.
- Inner folds exclude the outer bearing.
- Every outer model is checked to have been trained on exactly 6 bearings, none of them the held-out one.
- INT8 calibration uses the training bearings only.
- The locked test bearings B06, B07, B13 and B17 are never loaded.

**Exploratory versus unbiased (corrected after the independent review).**

The whole candidate set was shaped by Run 2's held-out results on B02–B04:
- weight decay 0.01 was picked there;
- the log inputs answer Run 2's finding that every end-stage row sits at the clip;
- the no-temperature option answers Run 2's x8 check.

The latch was adopted after Run 1's flicker on B02–B04 (introduced in Run 2); the 0.5 threshold and the 50 %
temperature dropout were fixed in Run 1's design. The thermal-model thresholds were drawn from B01 and B03's temperature
curves.

**So B02–B04 are exploratory folds for every candidate, A included** (A is scored with the latch adopted after Run 1,
and its temperature input uses thresholds drawn from B03), and only **B08, B09, B11 and B12 give unbiased
estimates.** The results are reported for both groups (section 11).

The Run 3 script and `DESIGN.json` were written after the new bearings' preprocessing summaries had been printed
(clipping counts, temperature masking, detector alarm ids), but before any network was trained on them and before any
labelled-row outcome was inspected. The candidates themselves come from Run 2 and from the requested study list:
weight decay, clipping, temperature.

### 7.3 Independent review of the protocol

Before the results were trusted, three independent reviewers (separate agents) read the code and the saved outputs, each
with a different focus: leakage, correctness and evaluation design. Every serious finding was then checked again by a
separate agent asked to refute it.

**Confirmed clean:**
- inner folds exclude the outer bearing;
- the selection for an outer bearing uses only its inner results (recomputed on one case);
- the validation-loss curve does not change the weights (bit-identical with and without it);
- INT8 hidden scales use training bearings only;
- no locked test bearing was loaded or even processed.

**Confirmed problems, all handled in this report:**
- the "unbiased" label must be restricted to the four new bearings;
- the labelled-row metrics are met by construction;
- the selection tie;
- B12's commissioning step;
- the temperature confound;
- the unfair parts of the reference comparison;
- the missing constant-speed regime;
- the v1 RTL row sampling;
- the INT8 dead-neuron overflow.

Minor code items (an unenforced reproduction assert, a missing digest recomputation, no Z-cap define in the C header)
were checked by hand. The reproduction and the label digest both hold, and the npz labels match the label table
exactly.

## 9. Training Results and Learning Curves

![Learning curves](../../model/results/supervised/run3/analysis/figures/learning_curves_run3.png)

- **Training loss.** Without weight decay (A), the training loss falls to 0.0005. (Run 3's "final training loss" is
  the mean of the last 25 steps; Runs 1–2 stored the last step's loss.) With weight decay (B–E) it levels off
  at 0.015–0.021, because the penalty stops the weights from growing without bound.
- **Validation loss** on the held-out bearing's labelled rows (recorded every 25 steps, **never used to stop training
  or to choose anything**):
  - A reaches its minimum of about 0.11 near step 300, then **rises** to about 0.16 while its training loss keeps
    falling. The rise comes from B11 and B12, where A becomes confidently wrong: its end-stage scores fall towards 0.
    On the other five bearings A's validation loss keeps falling. That is over-fitting into over-confidence.
  - B–E settle at 0.022–0.033.
- **Mean |logit| on the held-out rows** grows to about 19 for A but stays at 4–7 for B–E. The scores of the
  regularised models are much less extreme.

  unregularised network is not reliably reproducible across seeds.

## 11. Accuracy, Precision, Recall, F1 and Confusion Matrices

These scores are computed on the labelled held-out rows only: 100 healthy and 5 end-stage rows per bearing, which is
3,675 rows per candidate over 7 bearings × 5 seeds. The anomaly detector and B02's 6.5 g limit have one run per bearing
(735 rows).

{{T_SCORES}}

![Confusion matrices](../../model/results/supervised/run3/analysis/figures/confusion_run3.png)

These row-level numbers carry little information. Two trivial rules, which use no learning and no data, show why:

{{T_TRIVIAL}}

- Healthy rows can only be falsely alarmed inside the commissioning window, where the inputs are near 0 by construction.
- For the latched MLP alarms and the anomaly detector, all end-stage rows of a bearing are caught or missed together, by
  one latch. (B02's 6.5 g limit latches inside B04's end stage and catches 2 of its 5 rows.)

**The evidence that matters is per bearing.** The table below gives exact (Clopper–Pearson) 95 % intervals; seeds do
not add independent evidence, because every candidate gives the same outcome on a bearing for all 5 seeds.

{{T_BEARINGLEVEL}}

How to read the row-level numbers above:
- **With the latched alarm, all 25 false negatives for every MLP candidate are B12's end-stage rows** (5 rows × 5
  seeds), and every other bearing's end stage is caught. With the raw score > 0.5, C misses 21 (one B12 end-stage row
  scores above 0.5 in 4 of 5 seeds) and A misses 46 (B12's 25, plus 21 on B11 where its score falls back below 0.5).
- **The latched alarm has no false positives.** With the raw score > 0.5, E has 3: the same B11 healthy row (M0073) in
  seeds 1–3, a single score of 0.51–0.54 that is never 3 in a row.
- **The scores are dominated by the easiest rows** (brand-new against worn-out), so they are not an estimate of
  accuracy in service.
- **The anomaly detector scores higher** (recall 1.0) because it also catches B12.

## 13. Run 1 vs. Run 2 vs. Run 3 Comparison

Runs 1 and 2 evaluated only B02–B04 and trained each fold on 2 bearings; Run 3 trains each fold on 6. Each cell gives
the first alarm in minutes before the last record, then the alarm-state changes of the same unlatched rule (on while
the last 3 scores are above 0.5), so the counts are like-for-like; the deployed latched alarm changes once.

{{T_RUNS}}

![Run 1, Run 2 and Run 3 on B02–B04](../../model/results/supervised/run3/analysis/figures/runs_compare_run3.png)

**What improved:**
- **Stability:** 1 change on B02–B04 for E, against 9–17 (B02), 1–3 (B03) and 43–47 (B04) for Run 1.
- **Earlier first alarms:** on all three bearings, by 0.5–3.7 min on B02, 9.1 min on B03 and 4.2–14.0 min on B04.
- **Less over-confidence:** scores below 0.001 or above 0.999 fall from 87.1 % (Runs 1–2, B02–B04) to 1.1 % for E on
  the same bearings (0.8 % over all 7).
- **Reproducibility across seeds.**

**What did not improve:**
- **The MLP is still later than the anomaly detector.**
- **More data alone does not help.** The Run 1–2 settings trained on 6 bearings (Run 3 A) flicker *more* (19–21, 3–5
  and 65–75 changes), and their first alarm varies more between seeds on B02 and B03.
- **A new failure appears:** B12.

**Comparability.** Runs 1–2 never saw B08–B12, so on those bearings Run 3 has no earlier run to compare with. Run 3's
B02–B04 folds were trained on 6 bearings, so the comparison mixes the effect of more data with the effect of the new
settings. Run 3 A separates the two.

## 14. Comparison Against the Original Anomaly Detector

| Criterion | MLP (selected E) | Anomaly detector (A, F42, speed) |
|---|---|---|
| Needs labels | yes (healthy and end-stage) | no (fits each bearing's own first 100 measurements) |
| Healthy-reference false alarms | 0 | 0 (1 row above threshold per bearing, in-sample) |
| End-stage recall | 6 of 7 bearings (misses B12) | **7 of 7** |
| First alarm | later or equal on every bearing | **earlier or equal on every bearing** |
| Stability (alarm-state changes, unlatched) | mean 0–9 per bearing (0 on B12, which never alarms; up to 21 on one B11 seed) | 1–14 per bearing (14 on B12, 9 on B09, 7 on B08) |
| Latched alarm changes | 1 (none on B12) | 1 on every bearing |
| Runs on 64 kHz data | yes | the F42 version yes; the original F128 prototype no |
| Hardware | 8 × 8 array, 1.78 µs | ARM only (no network) |

**Verdict: the trained MLP does not outperform the anomaly detector.** Under Run 3's own selection rule the detector
would rank first: 0 healthy rows alarmed and 7 of 7 end stages latched, against 6 of 7. The MLP's first alarms coincide
with the detector's on five bearings (2–19 measurements later), come about 3.5 hours later on B08 and never come on
B12. Its
one advantage is a steadier raw score on B08 and B09.

The reason is structural:
- The anomaly detector's threshold is the 99th percentile of the bearing's own healthy scores, so it flags any
  departure from normal.
- The network's decision boundary is learned from labels that are all extreme, so it waits for a large departure.
- Until labelled intermediate stages exist, a supervised network trained this way cannot be expected to warn earlier.

## 15. Prediction Confidence, Calibration and Input-Clipping Analysis

### 15.1 Over-confidence

- **Without weight decay** (A), 88.9 % of all held-out scores are below 0.001 or above 0.999, with a mean |logit| of
  19.9.
- **With weight decay, log inputs and no temperature input** (E), that share is 0.8 % and the mean |logit| is 4.3 (C:
  3.4 % and 4.4). Scores in the unlabelled
  middle spread out: 19.8 % fall between 0.05 and 0.95.
- **The price is a smaller safety margin on healthy rows.** E's highest healthy score is 0.54 (B11, against 0.23 for
  A). One B11 healthy row, M0073, went above 0.5 in three of the five seeds (0.51–0.54); it was a single spike, never
  three in a row, so no alarm was raised.

![Raw score distributions, selected configuration E](../../model/results/supervised/run3/analysis/figures/scores_E_wd_slog_noT_run3.png)

### 15.2 Calibration

**Calibration still cannot be verified.**
- On the labelled rows the log-loss is low (0.025 for E).
- But those rows are only the two extremes, and the unlabelled middle has no ground truth.
- Class balancing (50 % end-stage in every batch, against 4.8 % in the labelled rows) also shifts the scores upward by
  design.

The output must be read as a **deterioration score with a threshold**, not as a probability of failure.

### 15.3 Does the ±16 clip hide information?

**Yes.** On B04 the ln-RMS input keeps rising from 16 to about 39 over the last 3 hours while the clipped network input
stays at 16. Among the clipped rows, the Spearman rank correlation between the raw value and time is 0.83 for ln RMS
and 0.86 for both band energies. B03 (0.67–0.73 for ln RMS and the 1–5 kHz band) and B11 (0.61–0.63) show the
same. The share of rows with at least one input
clipped is 10–64 % per bearing (table in section 5).

![Clipping](../../model/results/supervised/run3/analysis/figures/clipping_run3.png)

**Effect of removing the clip** (log-compressed inputs, C against B):
- the mean unlatched alarm-state changes fall from 15.5 to 2.9;
- B04's flicker goes from 7–35 changes to 1;
- the share of extreme scores falls from 37.5 % to 3.4 %.

In relative terms this is the largest single improvement in Run 3 (changes −81 %, extreme scores −91 %); in absolute
terms adding weight decay (A → B) removed more (30.3 → 15.5 changes). The nested selection chose a log-input candidate
on every one of the 7 outer folds.

### 15.4 Why B12 is missed

![B12's end stage on the rear sensor](../../model/results/supervised/run3/analysis/figures/diagram_why_b12.png)

On every other bearing the end-stage rows reach a largest vibration z-input of 18–51. On B12 they reach only 2.5–3.2,
inside B12's own healthy range (up to 3.5).

Two facts from the data review explain this:
1. B12's stop was most likely triggered by the **front** accelerometer (8.5 g against 4.9 g on the rear).
2. A **lasting step at M0061** inside B12's commissioning window inflates its reference spread.

**A post-hoc check, explicitly not part of the evaluation** (`run3_b12_diagnostic.py`): re-commissioning B12 on
M0061–M0160 halves the spread (0.501 → 0.234). Even then the end-stage z reaches only 2.3–4.1, and the held-out E models
alarm on just 2 of 5 seeds (18 min before the end). The anomaly detector alarms 40.8 min before the end either way.

### 15.5 The temperature shortcut

- **The shortcut.** x8 is exactly 0 on every healthy label (the thermal model is still calibrating) and non-zero at the
  end stage, so it separates the labels for a reason that has nothing to do with physics.
- **Data problems on top of it.** B11's T1 sensor fails later in the run, and B08's x8 is masked.
- **The evidence:**
  - Removing x8 (D against B, E against C) leaves recall and healthy false alarms unchanged and makes no consistent
    difference to stability (20.7 against 15.5 changes; 2.8 against 2.9).
  - Re-scoring the trained models with x8 = 0 shows where temperature does matter: B's early alarms on B11 move
    15–124 measurements later, and C's alarm on B09 moves 23 measurements later. These earlier alarms are driven by the
    temperature residual, but not by a saturated input or the failed sensor: at B's B11 alarms x8 is +12.7 to +13.8 σ,
    below the clip, and T1 still agrees with T2 (x8 saturates only from M0724, the T1 fault starts about M0979).
- **The end-stage temperature values contradict each other across bearings,** so the temperature study is
  **inconclusive**:

{{T_X8}}

  B11's end-stage x8 is −60 σ, because its T1 sensor dropped out. B08's is 0 (masked). The others are +1.8 to +31 σ. A
  network cannot learn a consistent temperature signal from these 7 bearings.
- **Conclusion:** the temperature input currently adds no measurable value and carries two risks, so E's choice to
  ignore it is defensible, but the data cannot show whether temperature would help with a working sensor and a
  validity flag.
- **The team's call.** If the specification requires temperature, **C** is the equivalent alternative. It was trained
  and exported as well (section 16).

## 16. INT8 Quantization and RTL Verification

### 16.1 A bug found and fixed in the export path

- **The bug.** Weight decay drives the weights of some dead hidden neurons to about 1e-35. `export.build` then gives
  that output channel a scale of about 1e-37, so its bias quantizes to about 1e24, which overflows the INT32 bias and
  the cast.
- **The extent.** It affected 31 of 175 outer models and 2 of the 5 final E models (seeds 1 and 2). It did not change
  any INT8 decision in this run (the dead neurons output 0 either way): the first INT8 numbers in `train/results.json`
  are identical, row for row, to the fixed ones in `hardware/`, and none of the networks exported or RTL-simulated in
  v1 was affected. But the exported biases would not fit the hardware's 32-bit register, so the fix is required.
- **The fix** (`run3_hardware.py`, export path only; `export.py` and the trained weights are unchanged): weights with
  |w| below 10⁻⁶ of their layer's largest are set to 0 before quantizing, and every hidden-layer bias is asserted to fit 32 bits (the output-layer bias, added by the ARM, is about
  10³).
- **Checked:** the FP32 output changes by **exactly 0** on every row. 136 of 175 outer models contained such dead
  weights.

### 16.2 FP32 against INT8 on every development bearing

Each model is checked on every row of its held-out bearing, through the bit-exact golden model (22-bit accumulator).
Hidden scales come from the training bearings only.

{{T_INT8}}

![INT8 decisions changed](../../model/results/supervised/run3/analysis/figures/int8_run3.png)

- **E** changes 13 of 45,015 decisions (0.03 %), the fewest of all candidates, and its latched first alarm is identical
  in all 35 networks.
- **Labelled rows:** E changes 3 (one B11 healthy row in each of three seeds, each a score near 0.5).
- **C's final models** change 37 of 45,015 decisions (in-sample), none on a labelled row.

### 16.3 RTL simulation of the trained networks

`tb_mlp.sv` was run on the accelerator RTL, with `rtl_check.PARAMS` (P = 8, ACC = 22) and Icarus Verilog, against the
golden model: every raw output sum, the last layer's buffer and every counter were compared.

{{T_RTL}}

The final C model (seed 0) also passed (24 batches of 64 and 10 single rows, 1,642 and 382 cycles). The cycle counts
equal the hardware equation, `mlp_equation`, in every run.

The review noticed that the first RTL pass (v1) simulated only a prefix of each bearing's rows. The v2 runs above sample
a spread of rows, and a supplementary run (`run3_supplement.py`) simulated **all 735 labelled rows, including all 35
end-stage rows**, for the seed-0 final E and C models (12 batches of 64, the last topped up): **PASS, bit-exact**.

| Batch | Cycles | Latency at 214.286 MHz |
|---|---|---|
| 1 measurement | 382 | **1.78 µs** |
| 64 measurements | 1,642 | 7.66 µs (0.12 µs per measurement) |

**The 8 × 8 array supports the network without any architecture change:** 14 array passes, INT8 inputs, all

## 17. Current Limitations and Uncertainties

- **The bearing is the independent unit, and there are 7.** 6 of 7 latched (95 % interval 0.42–1.00); on the four
  unbiased bearings 3 of 4 (0.19–0.99). No claim of a detection rate is possible.
- **The labelled-row metrics are met by construction.** A trivial "latch after commissioning" rule matches or beats
  every candidate on them.
- **35 end-stage labels from 7 bearings.** Every one comes from the last 1–2 minutes of a test (48–114 s). The 30 from
  six bearings are at an extreme state (largest vibration z-input 18–51); B12's 5 reach only 2.5–3.2.
- **The labels are provisional and unreviewed.** B12's healthy window contains a vibration step, and for B11 and B12 the
  end labels rest on a stop probably triggered by the front sensor (the rear never reaches 6.5 g). On B12 the rear sensor
  barely registered it; on B11 it rose clearly (vibration z 48–51).
- **The onset of damage is unknown.** First-alarm times are not detection delays. "Earlier" is not verifiably
  "better".
- **The selected MLP does not beat the anomaly detector,** and it misses one of seven bearings.
- **In the final selection, the rule's first two criteria tied** for every candidate. The choice fell to stability, a
  label-free proxy, and E and C are within noise of each other (2.80 against 2.86 changes). In the nested selection,
  inner recall differed on B04, B11 and B12 and decided the pick (C) on B04 and B11.
- **The healthy-row margin is smaller** with weight decay (highest healthy score 0.54).
- **Scores are not calibrated probabilities.**
- **The 64 kHz bearings** are compared with the (A, F42, speed) detector, not the original F128 prototype.
- **The candidate set was designed from Run 2's held-out B02–B04 results** (and the thermal thresholds from B01/B03),
  so B02–B04's folds are exploratory for every candidate, A included (it is scored with the latch adopted after Run 1).
- **The constant-speed regime (B14–B17) is not covered** by any development bearing, but B17 is in the locked test set.
- **The 6.5 g reference is B02's logged limit applied to the rear sensor,** not the rig's actual rule on the new
  bearings, whose limit and channel are undocumented.
- **Only one accelerometer,** the rear one, while two stops were probably triggered by the front one.
- **Hardware results are simulation only.**
- **The Motor Health Index is untrained.**
- **The locked test bearings have not been evaluated.**

## 18. Recommended Improvements for Training Run 4

1. **Teach the network intermediate stages, or stop asking it to find them alone.** Options to evaluate under the same
   nested protocol:
   - Combine the two detectors: use the anomaly detector's per-bearing threshold as an input or a gate, and the MLP as
     a confirmer.
   - Extend the end-stage labels with the sensitivity windows already defined (END_N 10 or 20), declared in advance.
   - Express the MLP's score relative to its own commissioning distribution, as the anomaly detector does.
2. **Add a commissioning-validity check for vibration,** like the thermal V1–V3 rule. It would have flagged B12's step
   at M0061. Decide before Run 4 whether such bearings are re-commissioned or excluded.
3. **Decide the sensor question.** Two stops were probably triggered by the front accelerometer. Either confirm with the
   dataset authors which channel the limit used, or evaluate a front-sensor (or max-of-both) variant of the six
   vibration features, which keeps 8 inputs.
4. **Make the log-compressed inputs the default** (C or E), and move the dead-weight zeroing and the INT32 bias check
   into `export.py` itself.
5. **Temperature:** redesign x8 with an explicit validity flag and a T1/T2 consistency check (B11's T1 failure), or
   keep it disabled (E).
6. **More bearings:**
   - B10 (64 kHz, outer race), B14 and B15 (constant speed, the last regime not yet seen);
   - B05 and B16 only for their commissioning rows: both were found damaged at dismantling and lack end-stage labels
     only because B05 was interrupted and B16 has no stop criterion, so the rest of their recordings cannot be counted
     as healthy.
7. **Choose the threshold on the inner folds** rather than fixing it at 0.5. B12's end-stage scores of 0.25–0.41 show
   the fixed threshold matters.
8. **Freeze one model, then evaluate it once on B06, B07, B13 and B17,** and report the result whatever it is.

## 20. Final Conclusion

**What Run 3 accomplished:**
- **Data:** four new run-to-failure bearings, from two new operating regimes, integrated with full integrity checking
  and a documented data review. That more than doubles the labelled development data.
- **Validation:** a leak-checked, nested leave-one-bearing-out evaluation of five configurations, reproducible bit for
  bit.
- **Stability:** log-compressed inputs with weight decay make the network much steadier and less over-confident, and
  bring its first alarm close to the anomaly detector's on five of seven bearings (about 3.5 h later on B08, never on
  B12).
- **Hardware:** the trained network passes INT8 and bit-exact RTL verification on the unchanged 8 × 8 accelerator, at
  1.78 µs of accelerator compute per measurement (382 simulated clocks at 214.286 MHz; bus transfers and ARM work not
  included), after a real export bug was found and fixed.

**What it did not achieve:**
- **The network does not outperform the label-free anomaly detector.** It never warns earlier, and it misses B12.
- **The likely cause** lies in what the labels teach (only extreme end stages), in B12's data (a commissioning step,
  and a stop probably triggered by the other sensor) and in the fixed 0.5 threshold, not in the hardware: the FP32
  models miss B12 too. The network size was never varied, so it is not ruled out.
- **Still open:** the Motor Health Index stays untrained, and every hardware result is from simulation (the detection
  results come from the recorded data, processed offline).

**Next:** combine the strengths of the two detectors, add a vibration commissioning check, settle the sensor question,
and evaluate a frozen model once on the locked test bearings.
